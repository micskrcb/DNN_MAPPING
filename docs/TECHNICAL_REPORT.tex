\begin{abstract}
This report documents an implementation and experimental study of core
placement for multi-chip, many-core DNN accelerators. The project is an
independent reconstruction motivated by Wu et al.'s 2020 TODAES paper on
reinforcement-learning-based core placement. Because the original simulator and
several parameters were not released, this work does not claim exact numerical
reproduction. Instead, it makes all reconstruction assumptions explicit.

The system partitions DNN layers into vector-matrix-multiply (VMM) and
vector-vector-accumulation (VVA) logic cores, maps them to a hierarchical
multi-chip mesh, and minimizes a reconstructed bottleneck pipeline latency.
The repository includes random search, fixed simulated annealing (SA), adaptive
SA, DDPG, guided DDPG, masked PPO, PPO-guided SA, and contextual-bandit-guided
SA. The active method is a contextual bandit that ranks legal SA proposals while
fixed SA retains temperature control and Metropolis acceptance.

Current results provide positive matched-control evidence for the contextual
bandit on AlexNet-FC and VGG16-FC. They do not yet prove superiority over the
strongest non-learned proposal heuristic, over fixed SA on every workload, or
over a broader class of accelerators. This report explains the theory, code,
experimental evidence and limits needed to extend the project responsibly.
\end{abstract}

\section{Scope and research question}

The goal is to assign every DNN logic core to a distinct physical core so that
the latency of the slowest pipeline stage is minimized. The reference problem
comes from Wu et al., ``Core Placement Optimization for Multi-chip Many-core
Neural Network Systems with Reinforcement Learning,'' ACM TODAES 2020,
DOI~\href{https://doi.org/10.1145/3418498}{10.1145/3418498}.

The project distinguishes three progressively stronger claims:

\begin{enumerate}[label=\arabic*.]
  \item The program produces legal placements and finite costs.
  \item A trained learner changes its scores and decisions relative to a frozen
  control.
  \item Under matched mechanics and equal objective-evaluation budget, the
  learner improves the optimizer's final result.
\end{enumerate}

Only the third is an optimizer claim. A single low best-so-far value does not
prove learning: it can arise from random exploration, initialisation or an
external repair heuristic.

\section{Hardware and workload reconstruction}

\subsection{Physical topology}

The paper-oriented configuration has a $4 \times 4$ array of chips. Each chip
contains a $16 \times 16$ mesh of processing cores, for

\begin{equation}
N_{\mathrm{physical}} = 4 \times 4 \times 16 \times 16 = 4096
\end{equation}

physical cores. The implementation is in
\code{src/multi\_chip\_topology.py}. A global core ID is chip-major; helper
functions recover chip and local coordinates.

The active paper-oriented routing model, \code{paper\_xy}, uses dimension
ordered routing. Intra-chip traffic follows XY routing in the local mesh.
Inter-chip traffic routes from the source core to a lower-left chip-periphery
gateway, travels X then Y across the chip array, then travels from the target
gateway to the destination core. This gateway choice and detailed global
routing-switch behaviour are reconstruction assumptions.

\subsection{DNN logic cores}

The workload extractor in \code{src/run\_multi\_chip.py} traces supported
Torchvision models and represents every layer with a two-dimensional partition
grid. For $M$ output-channel groups and $N$ input-channel groups, the layer
contains $MN$ VMM cores and $M$ VVA cores. VMM tasks compute partial products;
VVA tasks accumulate partial sums and emit activations.

\code{src/compute\_model.py} implements the partition reconstruction. In
\code{paper\_targets} mode, it selects per-layer $(M,N)$ grids that match the
aggregate logic-core totals reported in the reference paper, satisfy the
64~KB 8-bit weight-tile restriction, and balance estimated VMM/VVA work.

The paper does not publish individual layer grids, VVA execution rate or the
logical indexing order. These settings are documented reconstruction parameters,
not recovered ground truth.

\subsection{Compute timing}

VMM timing uses 128 MACs per cycle at a 400~MHz clock. VVA timing uses the
explicit parameter \code{--vva\_ops\_per\_cycle}, because the paper does not
publish that rate. For task $i$,

\begin{equation}
t_{\mathrm{comp}}(i) =
\frac{\left\lceil operations_i / (rate_i\,u) \right\rceil}{400\text{ MHz}},
\end{equation}

where $u$ is assumed arithmetic utilization. The model excludes several
unpublished factors, including detailed packet scheduling, activation-buffer
stalls, router startup and exact compute/communication overlap.

\section{Placement objective and evaluator}

\subsection{Legal placement}

Let $P(i)$ be the physical core assigned to logic task $i$. A placement is
legal when every assignment is in the allowed physical-core region and
$P(i) \neq P(j)$ for $i \neq j$. \code{MultiChipEnvironment} in
\code{src/multi\_chip\_environment.py} owns this state, validates legality and
calculates cost.

The code can allocate disjoint whole-chip masks to convolutional and
fully-connected regions, matching the paper's high-level separation of these
workload classes.

\subsection{Bottleneck pipeline latency}

The primary objective is reconstructed bottleneck pipeline latency, not summed
wirelength. Kahn topological levels form task stages $S_k$. The objective is

\begin{equation}
L(P) = \max_k T_k(P).
\end{equation}

In the basic task-sum model, a placed source task has service time

\begin{equation}
t_i(P) = t_{\mathrm{comp}}(i) +
\sum_{j \in \mathrm{succ}(i)} bytes(i,j)\,c(P(i),P(j)),
\end{equation}

and stage time is the largest service time in that stage. Under
\code{paper\_pipeline}, the evaluator constructs explicit XY routes and models
shared directed-link serialization. For each phase it uses the larger of the
largest single-source routed traffic time and the most loaded directed link.

The methods \code{pipeline\_stages()}, \code{pipeline\_breakdown()} and
\code{\_xy\_contention\_components()} implement this calculation.

\subsection{Why sensitivity is checked first}

An optimizer cannot reliably improve a nearly flat objective. Earlier AlexNet
CONV partitioning concentrated work in a placement-independent VVA task,
creating an apparent optimization problem with almost no real headroom. The
current runner samples random legal placements before long paper-mode runs and
can stop if the observed relative objective span is too small. The bypass flag
\code{--allow\_flat\_objective} is intended for diagnostics, not normal
experiments.

\subsection{Incremental exact evaluation}

SA moves relocate or swap only a few tasks. \code{IncrementalPipelineEvaluator}
in \code{src/run\_multi\_chip.py} caches unaffected stage costs and evaluates
only stages affected by a candidate move. It is designed to agree with complete
evaluation while allowing large SA budgets. Full-evaluation flags remain
available for debugging and reference checks.

For fixed SA, a candidate $P'$ is accepted automatically if
$\Delta = L(P') - L(P) \leq 0$. Otherwise it is accepted with probability

\begin{equation}
p_{\mathrm{accept}} = \exp(-\Delta/T).
\end{equation}

The initial temperature is calibrated from uphill candidate deltas to target an
initial acceptance probability, normally 0.8. Temperature then cools
geometrically with the paper-oriented factor 0.99. This calibration replaced
historical absolute temperatures that were inconsistent with a seconds-valued
objective.

Adaptive SA adjusts temperature and move scale over windows to target an
acceptance rate near 0.30. It is a useful comparison, but its current controller
has generally performed worse than calibrated fixed SA on the evaluated
settings. That is a result about this controller, not a general rejection of
adaptive metaheuristics.

\section{Retained reinforcement-learning methods}

\subsection{Continuous DDPG}

The original paper-oriented DDPG path has actor and critic networks that emit
continuous coordinates and estimate action values. It supports an MLP, a spatial
CNN and a Figure-9-inspired CNN. Actions are discretized and collision-repaired
when several tasks map to the same physical core.

This repair causes a credit-assignment problem: replay stores the actor's
continuous intent while the evaluator sees a substantially different repaired
placement. Earlier diagnostics showed high repair rates and degenerate intended
positions. The DDPG implementation is therefore retained for historical audit,
not treated as the active solution.

\subsection{Guided DDPG and masked PPO}

\code{run\_ddpg\_guided()} attempts to improve DDPG with legal candidates,
ASA demonstrations, prioritized replay, twin critics and behaviour cloning.
\code{run\_masked\_ppo()} places tasks autoregressively with an exact mask over
occupied and disallowed cores, eliminating collision repairs. Its PPO objective
is

\begin{equation}
L^{\mathrm{CLIP}}(\theta) = \mathbb{E}_t
\left[\min\left(r_t(\theta)\hat{A}_t,
\operatorname{clip}(r_t(\theta),1-\epsilon,1+\epsilon)\hat{A}_t\right)\right].
\end{equation}

These methods demonstrate legal-action mechanics but have not provided a robust
final-quality gain over strong SA baselines in the documented experiments.

\subsection{PPO-guided SA}

The PPO-SA path ranks a dynamic set of legal neighbor moves while SA retains
candidate generation and Metropolis acceptance. The
\code{reference\_separate} update style uses disjoint actor and critic modules,
separate optimizers, reward-to-go value targets and GAE-style advantages. It was
informed by the independently adapted training structure of the public
RL-Based-SA project, whose attribution is recorded in
\code{THIRD\_PARTY\_NOTICES.md}. Long tests did not establish a reliable PPO
proposal advantage, motivating a simpler one-step learner.

\section{Active method: contextual-bandit-guided fixed SA}

\subsection{Design}

The active method retains fixed SA's global optimization mechanics and learns
only to choose a move from a legal candidate set. This is a contextual-bandit
formulation because one objective evaluation reveals the selected proposal's
immediate gain. It avoids using a long-horizon value model when the supervised
signal is naturally one-step.

At each SA step, the system creates $K=16$ legal candidate moves. In the active
configuration, half are anchored on current bottleneck-stage tasks and half are
ordinary legal proposals. SA remains responsible for initial placement,
candidate legality, temperature, uphill-move acceptance and best-so-far
retention.

\subsection{Candidate representation}

Each proposal receives nine features:

\begin{enumerate}
  \item bottleneck-stage membership;
  \item VVA-task indicator;
  \item normalized task work;
  \item task work fraction within its stage;
  \item predecessor-hop change;
  \item successor-hop change;
  \item traffic-weighted hop change;
  \item same-chip connectivity change;
  \item an inexpensive routed-communication \code{proxy\_gain}.
\end{enumerate}

The global context contains chain progress, previous objective delta, previous
accept/reject state and recent acceptance fraction.

\subsection{Bandit network and update}

\code{ProposalBanditRegressor} uses a global-state encoder and candidate
encoder, each a one-layer 128-unit \code{tanh} MLP. Their embeddings are added,
nonlinearly transformed and passed to a scalar score head. The score head is
initialised to zero. Before learning, all candidates have equal score, which
makes the frozen control exactly uniform.

For selected proposal $P'$, the normalized signed proposed reward is

\begin{equation}
r = \operatorname{clip}\left(\frac{L(P)-L(P')}{s},-10,10\right),
\end{equation}

where $s$ is the reward scale. Positive reward means the proposal improved the
objective before the Metropolis accept/reject decision. The network minimizes
smooth-L1 loss,

\begin{equation}
\mathcal{L}_{\mathrm{bandit}}=
\operatorname{Huber}\big(\hat{r}(g,x),r\big),
\end{equation}

using uniform replay and AdamW. Uniform replay is deliberate: an earlier
positive-balanced replay scheme overrepresented rare gains and led to harmful
overprediction.

\subsection{Exploration and controls}

After a uniform warm-up, epsilon-greedy selection gradually reduces random
selection to 0.50 across the entire run. This relatively high final exploration
rate is intentional because only selected candidates obtain labels.

The primary frozen control has the same candidate pool, warm-up, cooling,
acceptance rule, budget and random-stream structure, but makes no parameter
updates. A stricter \code{proxy\_greedy} control ranks candidates directly by
the hand-designed \code{proxy\_gain} feature; it tests whether the learned
model contributes beyond that heuristic.

\section{Current evidence}

The supported conclusion is deliberately narrow:

\begin{quote}
Under equal true-objective budgets and the same focused candidate pool, the
contextual-bandit selector improved over a focused-uniform frozen control on
tested AlexNet-FC and VGG16-FC workloads. It is not yet proven superior to the
best non-learned proposal heuristic, fixed SA across every workload, or a broad
class of accelerators.
\end{quote}

\section{Limitations and threats to validity}

\subsection{Evaluator fidelity}

The implementation is a documented sensitivity model, not the unpublished
reference simulator. The main gaps are exact global routing, VVA throughput,
activation-buffer stalls, detailed packet scheduling, router startup,
compute/communication overlap and logical task ordering. Paper-normalized
ratios should therefore be reported as reconstruction diagnostics rather than
exact reproduction proof.

\subsection{Causal attribution}

The frozen focused-uniform control isolates the package of trained scoring plus
the selected candidate representation. It does not isolate the learned model
from bottleneck focusing or \code{proxy\_gain}. The proxy-greedy control,
feature removal, focus-zero and shuffled-label studies are the appropriate next
ablations.

\subsection{Statistics and wall-clock cost}

Seeds are repeated stochastic executions, not independent workload instances.
Three-seed uncertainty intervals are descriptive and unstable. Every report
should provide individual seeds, complete-objective-call budgets, wall-clock
time and predeclared decision rules. Equal objective-call counts do not imply
equal wall-clock cost because learned SA constructs, featurizes and scores a
candidate pool and performs neural updates.

\section{Reproducibility protocol}

For every reported experiment:

\begin{enumerate}
  \item Record Git commit, model, workload region, topology, timing model,
  VVA rate, logical task order, seed and device.
  \item Run the objective-sensitivity preflight before large paper-mode search.
  \item Use matched complete-placement objective evaluations.
  \item Keep learning and frozen-control conditions identical except for
  parameter updates.
  \item Save configuration/report JSON, diagnostic JSONL, manifest and archive
  checksum.
  \item Report every seed and distinguish tuned, held-out and new-workload
  experiments.
\end{enumerate}

The active family is selected with \code{--algo ppo\_asa},
\code{--ppo\_asa\_learner bandit}, and
\code{--ppo\_asa\_annealing fixed}. Exact supported commands belong in the
repository README and \code{docs/IMP\_README.md}; experiment commands should
not be reconstructed from memory.

\section{Publication path}

The present result is suitable for a bounded workshop or reproducibility-style
submission only if claims remain matched to evidence. A stronger positive-method
paper needs:

\begin{enumerate}
  \item a longer proxy-greedy matched-control experiment;
  \item feature and candidate-focus ablations;
  \item more held-out seeds and at least one additional workload family;
  \item a frozen evaluator configuration and recoverable archives; and
  \item explicit reconstruction limits in the method and discussion sections.
\end{enumerate}

The defensible contribution is not that RL universally beats SA. It is a
contextual-bandit candidate-selection mechanism for fixed SA in a reconstructed
multi-chip DNN placement simulator, with matched controls, documented negative
results and a reproducible experimental methodology.
